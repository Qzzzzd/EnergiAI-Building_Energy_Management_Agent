# Generate building-energy reports

Use this Skill only after the user explicitly requests a report. Select one of
the four fixed report types and pass the public Artifact IDs explicitly:

- `integrated`: quality plus evaluation and/or future forecast
- `quality`: six-dimension data-quality report
- `forecast-evaluation`: historical backtest/evaluation report
- `forecast-future`: future load forecast report

Run the repository foreground lifecycle driver:

```bash
skill-run start --skill building-energy-report-generation \
  --request request.json --session-id <session_id> --turn-id <turn_id> \
  --workspace-root .
```

Resume a `needs_input` job with the same job ID:

```bash
skill-run resume --skill building-energy-report-generation \
  --job-id <job_id> --answers answers.json --workspace-root .
```

## Input contract

```json
{
  "report_type": "integrated | quality | forecast-evaluation | forecast-future",
  "title": "可选标题",
  "source_artifact_ids": {
    "quality": "可选",
    "processing": "可选",
    "evaluation": "可选",
    "forecast": "可选"
  },
  "narrative_blocks": [],
  "report_config": {}
}
```

Accept only public Artifact IDs. Do not accept raw files, DataFrames, Parquet
paths, absolute paths, native Bundle paths, or arbitrary report templates.
`report_type` is explicit; do not infer it from whichever source happens to be
available. Required source combinations and the status matrix are documented in
[`references/contracts.md`](references/contracts.md).

## Codex narrative pass

Before invoking `skill-run`, complete an evidence-grounded narrative pass when
the report is being generated by Codex:

1. Read only the compact `verified_artifacts` summaries and the specific public
   JSON/Markdown file exposed by a controlled `content_url` when the summary is
   insufficient. Never open raw data, Parquet, model files, or an unregistered
   workspace path.
2. Write one `narrative_block` for every fixed chapter whose required source is
   verifiable. A block must contain a concise `takeaway`, two-to-four natural
   paragraphs in `body`, and, when useful, `next_action`, `caveats`, and
   `chart_refs`.
3. Bind every block to at least one source Artifact in `evidence_refs` and the
   corresponding top-level fact namespace in `fact_refs` (`fact:quality`,
   `fact:processing`, `fact:evaluation`, or `fact:forecast`). Use canonical
   registered chart IDs in `chart_refs` only when the chart is actually
   available for this report.
4. For every selected chart and every rendered evidence table, add a
   `visual_notes` entry with `kind` (`chart` or `table`), the canonical chart
   ID or exact table caption in `ref`, and a short reader-facing explanation.
   Explain how to read the visual, what comparison matters, and what it cannot
   prove. The renderer supplies a deterministic note when Codex omits one.
5. Explain what the result means for an engineer or operator, but do not add a
   metric, status, time range, causal explanation, or accuracy claim that is not
   present in the cited facts. Do not turn a future forecast into a historical
   evaluation.

The low-level Skill still accepts an omitted `narrative_blocks` field for CLI
compatibility. In that case it creates a clearly marked deterministic fallback
for every available chapter; this keeps direct lifecycle runs readable but is
not a substitute for the Codex narrative pass.

## Evidence rules

1. Resolve each ID only from `artifacts/public-artifacts/<artifact-id>/manifest.json`.
2. Verify every listed file's safe relative path, MIME type, size, and SHA-256
   before using it. Use only the manifest summary, public JSON files, and
   validated visualization PNGs.
3. Accept source status `succeeded` or `partial`; propagate `partial` and all
   source warnings. Do not treat failed, cancelled, interrupted, or input-
   required work as report facts.
4. Match DatasetBundle, target point, processing/model chain, feature schema,
   and leakage-rule metadata when the public sources expose them. Same-session
   provenance alone is not a match. If a cross-result chain cannot be proved,
   keep sections independent and mark the report `partial`.
5. Never reread internal Parquet/Bundle data, recompute quality scores or
   forecast metrics, estimate peaks from raw previews, or invent a chart.
6. Render missing facts as `未提供` with an evidence-gap note. Render a usable
   partial report when at least one required source is verifiable; return no
   formal report when no required source is verifiable.

`narrative_blocks` are wording supplied by the Codex planning layer. Keep only
blocks with structured evidence and fact references, a professional paragraph
length, valid chart/table references, visual explanations, and numeric prose
that matches the cited fact namespace. Reject unsupported numeric prose or
source claims and use the deterministic chapter/visual fallback. The model may
explain and qualify the evidence but may not add numbers, causal claims, time
ranges, recommendations, or status changes.

## Output rules

Publish one immutable `building-energy.report` Artifact with two equivalent
user-facing formats: `report.html` for controlled in-app preview and
`report.pdf` for download/print. Both files must be generated from the same
verified sections, facts, and selected charts; the PDF must not trigger a new
upstream calculation.

The HTML must be offline and self-contained:

- embed CSS and validated PNG bytes;
- use fixed sections and the fixed chart registry;
- use the curated chart set: prefer one readable visual per analytical purpose,
  omit redundant single-value/text-on-canvas figures and dense visuals when the
  exact evidence table is clearer;
- do not include scripts, remote requests, external fonts, forms, iframes,
  uncontrolled links, CDN assets, or sibling files;
- keep the report below 20 MB and use no more than eight charts;
- show evidence metadata beside each section and chart without absolute paths;
- use Asia/Shanghai for display while preserving source timezone and units;
- show an `分析解读` block before facts, charts, and tables; expose narrative
  coverage and whether the report used Codex text, mixed text, or deterministic
  fallback in the report summary;
- place a reader-facing `图表解读` or `表格解读` immediately next to every
  rendered visual, with the same explanation and order in HTML and PDF;
- expose the Artifact through the existing `content_url`/ResultDetailsPanel
  boundary, not a new frontend route.

The PDF must be self-contained, use the same fixed chapter order, narrative
paragraphs, facts, tables, and embedded verified PNGs as HTML, contain no
active content or external references, and remain below the same 20 MB
per-format limit. Use 12pt (小四) for the main body, Songti for Chinese, and
embedded Times New Roman for Latin letters and numbers. If the required fonts
are unavailable, fail honestly with `DEPENDENCY_MISSING`; do not silently
substitute a compact Latin font. If PDF rendering is unavailable or QA fails,
fail the report job instead of publishing HTML-only output.

Read [`references/report-design.md`](references/report-design.md) when changing
the section skeleton, chart registry, visual tokens, or QA rules. Keep the
deterministic implementation in `scripts/` and test it with the Skill's
fixture-based tests before changing upstream compute Skills.
